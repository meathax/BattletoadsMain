# Resource optimization

These changes preserve memory capacity and video options while changing how
Quartus implements storage. No RBF is generated by the validation runner.

- NVRAM retains all 8 KiB. Initialization, host restore and CPU byte writes
  share one write port. Upload borrows the CPU read port while the CPU is
  paused, avoiding a second copy of the RAM. Registered word reads followed
  by byte selection allow Quartus to infer RAM instead of thousands of flops.
- Scaler input, output and filter line stores use packed 24-bit RGB words
  with explicit placement attributes. Record arrays caused Quartus 17 to discard
  the placement attributes. The address, clock, enable and latency logic is
  preserved. Deep line stores use M10Ks; shallow scaler FIFOs and filter stores
  use MLABs.
- The 64 KiB audio store uses M10Ks. Both loader and CPU interfaces retain their full address
  range, byte order, initialization and registered read latency. Moving the
  entire store, together with HQ2x buffers, exceeded the device's 985 MLAB
  locations; that allocation was rejected.
- Foreground scanout retains its 256 displayed columns in on-chip RAM. The
  other 768 logical bytes per row use reserved DDR storage, preserving the full
  CPU window and all 512 sprite destinations. CPU copies and off-screen sprite
  writes wait for their DDR transfers. Initialization skips the visible quarter.
- Automatic shift-register RAM recognition is disabled so short video
  pipelines use registers instead of consuming entire M10Ks.

The same working tree contains the dependent graphics corrections and their test
harness. Sprite drawing now retains the destination page selected at setup,
including when display control changes before the draw command.

## Verification

- Production audio RAM: all 65,536 initialized bytes, 32,768 loaded ROM bytes,
  32,768 CPU-written bytes, both lanes and bank boundaries, registered reads,
  both write owners and loader priority pass.
- NVRAM/platform tests: all 8,192 bytes, restore/upload, CPU lanes, save pause,
  foreign indices and reload pass; rotation and stalled DDR tests also pass.
- Scaler: all 16,777,216 RGB values pass through the actual VHDL codecs. After
  normalizing only the storage representation and attributes, the entire
  scaler source equals the pre-change snapshot, preserving its control logic.
- Graphics: 1,283 sprite configurations, 4,146 rows, 864 priority combinations,
  21 scroll cases, 1,024 scan pixels, 2,823 palette checks, 3,072 shift checks,
  28 register checks, 43 background reads and 2,048 destination-page checks
  pass with zero mismatches and zero refresh-wait errors. Coverage also includes
  2,048 independent upper-half bytes, 18,432 unaligned-copy bytes, 36 address-map
  checks and 78 checks that CPU copies preserve the video stream.
- Player-input tests pass all 256 DIP combinations and 6,150 CPU input reads.

The graphics oracle is the pinned MAME 0.289 row renderer; these tests exercise
production graphics through CPU bus stimulus. A separate native game-board
harness now executes the actual TMS34020, Z80 and DSP with the shipping DDR
controller. Earlier snapshots complete 1,800 gameplay frames. A fresh run checks
the current CPU arithmetic and qualified clock phases. The raster replay also
matches all five actual MAME title/gameplay PNGs using recorded display writes;
see `GRAPHICS_AUDIT.md` for its scope and receipts.

Quartus checks use `tests/graphics/synthesize.py`, which invokes only
`quartus_map`, `quartus_fit` and `quartus_sta` on an immutable source snapshot.
Receipts, reports and simulation logs remain in ignored local evidence/build
directories. The first successful placement,
`bt-graphics-115be86ca1c946829caf1b46de62cb03`, uses 534 of 553 physical RAM
blocks (97%), 20,266 of 41,910 ALMs, 19,991 registers and 35 DSPs. That fit
establishes resource feasibility; its negative timing slack prevents acceptance.
The previously attempted audio MLAB layouts were rejected and are not present
in the current RTL. Logical RAM-bit estimates alone did not predict physical
placement because port widths and depth geometry also determine block count.

Timing optimization retains the 80/160 MHz clocks and the original CPU/pixel
enable schedules. Foreground scanout separates its wide serial-word lookup from
byte selection. VRAM and video FIFO resets have local registers. The CPU keeps
its binary microstate and an equivalent one-hot shadow, bypasses arithmetic
loads, and computes bitmap transparency independently of the general RF source
selector. The decoder matches its pinned baseline across 4,476,224 comparisons;
the dependency check confirms that the write predicate affects only bitmap
writes. The independently verified 1-bit transparency correction is deliberate.

Both foreground and background serial output paths register wide-word lookup
separately from byte/word selection. Normal VRAM writes cross the two clocks as
complete packets. DDR cache commits use the captured request and banked tag
comparisons. CPU operands use the complete rising-phase interval, with parallel
high-half carry and coordinate-wrap comparisons. Numerical equivalence covers
524,288 carry16, 644,608 carry32, 1,283,072 extension and 1,290,048 wrap cases.

The user authorized an RBF only after full timing closure. Every available
operating corner is audited for setup, hold, recovery, removal and pulse width.
`tests/graphics/verify_timing.py` also requires matching fitted/workspace sources
and rejects provisional constraints. No RBF has been produced yet.

## Resource limits audit — 2026-10-06

Fit `bt-graphics-654227782468479ea0ac0b7d17826ce3` (before the RAM change below)
against the target/hard-limit table:

| Resource | Used | Hard limit | Status |
|---|---|---|---|
| Logic (ALMs) | 21,873 / 41,910 = 52% | 80% | pass |
| LABs used | 3,305 / 4,191 = 79% | 90% | pass |
| Peak interconnect (H/V) | 53.7% / 71.0% | 85% | pass |
| Average interconnect | 31.9% total | 60% | pass |
| RAM blocks (M10K) | 553 / 553 = 100% | 90% (497) | **over** |
| Block memory bits | 4,341,376 / 5,662,720 = 77% | 85% | pass |
| DSP blocks | 35 / 112 = 31% | 90% | pass |

Only RAM blocks exceed a hard limit. `VRAM_SHIFTREG` (synchronous mirror) was
inferred as eight separate 8-bit-lane RAMs: each foreground shift register used
8 blocks for 4 Kbit and the sprite mirror used 16 for 8 Kbit. It is now one
byte-enabled 64-bit-wide `altsyncram` (two blocks each), same function and
read-during-write behavior, saving about 26 blocks. `tests/shiftreg_sync_tb.sv`
compares it against the previous per-lane implementation using Altera's own
`altsyncram` simulation model (200,000 cycles including same-address
write/read collisions, address widths 9 and 10). The fit that confirms the new
block count has not been run; roughly 527 blocks (95%) is still expected, so
RAM remains over its hard limit until a further reduction is chosen.

Remaining reductions that were evaluated and not taken:

- Hq2x line stores (26 blocks): resizing them to 512 pixels changes output, and
  the control logic needs the 520-pixel margin. Removing the scandoubler loses
  the 31 kHz analog/direct-video output.
- Z80 program ROM into SDRAM (32 blocks): the BSMT sample reads use the SDRAM
  every sixth-clock enable and leave no full 7-cycle slot for Z80 fetches.
- BG VRAM upper byte: not removable. Each 16-bit BG word holds two pixels; the
  MAME renderer draws the upper byte as the second pixel (`bg0pix >> 8`).
- Audio RAM stays 32 KB: the Z80 boot code writes the whole 0x8000-0xFFFF range.
- Moving the BSMT ROM, NVRAM, HQ2x input buffers or FIFO into MLABs costs 40-130
  LABs per 4-8 blocks and would exceed the 90% LAB limit before reaching 497.

A mirror-to-blitter multicycle constraint (sprite source RAM to draw strobes)
was tried and rejected: in the graphics testbench the source word changes only
one memory cycle before the blitter samples it, so no two-cycle budget holds.

### Clock domains

The core uses three PLL outputs: `clk_sys` 80 MHz (master; CPU/Z80/DSP phases
come from clock enables), `clk_mem` 160 MHz and `clk_sdram_sample`. `clk_mem` is
a synchronous 2x of `clk_sys` from the same PLL; it gives the VRAM and DDR
interfaces two accesses per system cycle. `clk_sdram_sample` is a phase-shifted
80 MHz copy that registers only the 16 SDRAM data inputs: post-fit STA leaves a
window of about 1 ns (+0.013 ns setup, +0.929 ns hold), and a system-clock edge
falls outside it. Removing it means retuning the SDRAM clock phase and
re-closing both SDRAM interfaces on a fit, so it is kept. The pixel clock is a
steady 10 MHz enable, not a clock.

## RAM-block reduction — 2026-10-07

Fit `bt-graphics-ea4bec93e9554a6699003ee1ace690f6`: RAM blocks 541 -> 486 (88%),
ALMs 56%, LABs 81%, peak interconnect 83.7% (V), average 33%, block bits 76%,
DSP 31%. Every resource is under its hard limit. Each change keeps contents,
addresses, enables, latency and read-during-write behavior:

| Change | Blocks | Proof |
|---|---|---|
| BG VRAM split per byte into 5/2/1-bit RAMs; 5-bit parts limited to 2K depth (2Kx5 / 512x20) | -32 | `tests/vram_slice_tb.sv` (Altera model, 300k cycles) |
| HQ2x line stores: power-of-two M10K part plus a small register tail (1040 -> 1024+16, 520 -> 512+8) | -12 | `tests/hq2x_buf_split_tb.sv` (400k cycles) |
| Z80 audio ROM/RAM banks split 5/2/1 bits, 5-bit part at 2K depth | -8 | `tests/audio_ram_slice_tb.sv` (400k cycles, every cycle) |
| Shift-register mirrors in MLAB (async read + register) | -6 | `tests/shiftreg_sync_tb.sv` (Altera model, both widths) |
| `ascal` IHRES 2048 -> 1024 (largest input line is 1024 px with HQ2x) | -2 | input width bound |

A 128-frame native replay matches all 24 rasters. Moving NVRAM, the BSMT ROM
and the rotation FIFO into MLAB was measured and rejected: it saved 20 blocks
for about 4,600 ALMs and pushed LABs to 92%. Probe compiles showed that
Quartus 17 only uses the 2Kx5 mode for deep 5-bit RAMs when `maximum_depth` is
set, and that MLAB with an unregistered output does not honour old-data reads.
